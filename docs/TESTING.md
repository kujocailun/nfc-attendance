## 自动回归

| 范围 | 方法 | 本版结果 |
| --- | --- | --- |
| Python | `python -m unittest discover -s admin/tests -p "test_*.py" -v` | 41 项通过 |
| Web 状态 | `node --test admin/tests/test_status_refresh.cjs` | 12 项通过 |
| 固件主机桩 | `python tools/test_native.py` | attendance、network、button、feedback、storage 五组通过 |
| ESP32 构建 | `pio run -e s3_n16r8` | 发布前完整构建验证 |

Python 回归覆盖数据库持久化、CSV 严格校验、重复事件、USB mock 传输、网络配对与撤销、跨域路由、无效 JWT、任务重试和迁移。前端回归覆盖异步脚本初始化、延迟/失败响应、Wi-Fi 与 USB 状态优先级、撤销状态和重复任务按钮限制。

C++ 使用 C++17 和 `-Wall -Wextra -Werror` 编译。网络组包含原签到回归和 10 组远程场景，检查时钟读回、名单 ACK、历史逐记录 ACK、文件损坏、空历史、SD 故障、非法命令和登记幂等。其余组检查定时器、按键去抖、短写/短读、句柄关闭及禁止自动格式化。

主机桩验证状态与错误处理，不替代实际 SPI、供电、Wi-Fi 时序和 SD 介质测试。CI 生成的日志只使用合成测试数据。

## 实物验收范围

以下场景已在当前原型、生产后台和手机热点上完成。公开材料只记录结果，现场姓名、UID、设备 ID、域名与原始日志不随仓库发布。

| 场景 | 观察结果 |
| --- | --- |
| 首次及重复刷卡 | 成功提示后当日人数增加，重复刷卡显示已签到且不重复记数 |
| RTC 断电保持 | 整机断电后保留电池，重新上电时间继续走动 |
| SD 写入与重启 | 写入读回通过，重启后历史仍可读取 |
| 灯光和蜂鸣器 | 自检及刷卡反馈与预期一致，空闲时关闭 |
| 在线管理 | 远程登记、校时、名单上传、历史重扫收到相应确认 |
| 热点关闭 | 已登记卡仍按本地规则处理，离线命令保持排队 |
| 热点恢复 | 自动重连，排队任务完成，历史补传没有重复记录 |
| 整机双电源重启 | 时间正确，同卡重复刷卡维持当天人数 |
| 后台更新 | 生产后台更新并完成版本核验 |

现场回归使用少量测试卡和历史记录，能够证明本次操作流程。128 卡满名单、长期连续运行、存储介质耗尽、所有上电时序和生产电脑整机重启后的自恢复没有完成系统性实测。交付时保留这些边界，不按未测试项目宣称通过。

## 复测步骤

1. 先备份 SD 与后台库，检查线序、电源极性和 RTC。
2. 用新登记测试卡签到两次，检查终端、SD、后台只新增一条。
3. 关闭热点，刷卡并在后台创建一个允许排队的远程任务。
4. 恢复热点，等待设备在线和任务最终回执，重扫历史确认人数不变。
5. 按两路供电顺序整机断电重启，再刷同卡，检查当天记录仍被识别。
6. 导出 CSV 和 SQLite 备份，在隔离目录检查文件，避免用测试操作覆盖正式数据。

## 公开发布核验

公开版本从清理后的基线建立历史。发布前检查候选文件、Git 暂存区、所有提交历史和解压后的源码包，并使用独立密钥扫描工具复核。发布后从远端读取源码和标签，检查发布物与本地提交一致。

`tools/check_public.py` 检查私有文件路径、常见凭据格式、个人邮箱和本机用户路径，只报告文件与规则，不输出匹配值。它不能识别所有敏感数据，新增截图、日志、域名和样例时仍需人工审核。
