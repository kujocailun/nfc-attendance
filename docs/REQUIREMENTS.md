# 需求分析

## 使用角色与范围

签到者在现场刷实体 NFC 卡。管理员负责卡片登记、日期时间维护、记录查询与导出。部署维护者负责后台运行、域名接入、备份和凭据撤销。第一版支持一台联网终端和至多 128 个 UID，不实现多场地排班、请假审批和门禁控制。

## 功能要求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| F01 | 读取合法 4/7 字节 UID，支持登记到名单 | 未登记卡读 UID，登记后重新刷卡 |
| F02 | 同卡同自然日最多保存一条签到 | 连刷两次，记录和人数只增加一次 |
| F03 | 保存前验证 RTC、名单和 SD 状态 | 无效时拒绝提示成功 |
| F04 | 写入记录后重新读取确认 | 注入短写、损坏读回，返回失败 |
| F05 | 断电后保留名单、当天状态和时钟 | 双电源断电重启后重复刷卡 |
| F06 | USB 管理支持登记、校时、读取名单和历史 | 本地浏览器连接串口验证 |
| F07 | 热点关闭时继续本地签到，恢复后补传去重 | 断网刷卡、重连、重扫 |
| F08 | 网页远程操作排队，显示最终回执 | 离线发任务，重连后检查状态 |
| F09 | 后台支持筛选、人员备注、导出和备份 | 数据库与 HTTP 自动回归 |
| F10 | 管理页面与设备接口分域认证 | 错误 Host、无签名、错密钥请求被拒绝 |
| F11 | 配网信息由本地 AP 输入，候选配置验证后保存 | 错误候选不覆盖有效配置 |

## 数据与安全要求

终端原始记录至少包含时间、UID、姓名、状态。终端当天重复判断以本地 SD 为依据，网络事件重放不能产生新的签到。名单同步保留后台备注，不能默默改写已有姓名绑定。

管理员入口需要 Cloudflare Access 有效 RS256 JWT，并核对 issuer、audience、邮箱和有效期。设备使用独立随机密钥，后台保存其摘要，支持撤销。修改管理数据还需要页面会话令牌和来源校验。服务只监听回环地址，公网通过隧道接入。

热点密码、设备密钥、实际部署域名、人员信息和签到记录不得进入公开仓库。备份按私有业务数据处理。

## 非功能要求与边界

网络请求不能独占主循环；本地刷卡和 SD 操作由主循环处理，网络任务通过队列交换数据。故障必须有可观察的状态，禁止 SD 初始化失败后自动格式化。

目前未给出长期连续运行、128 卡满载和大规模历史扫描的实测性能承诺。OLED 使用默认字体，中文姓名可保存在后台，但不能保证在屏幕完整显示。UID 认证不防复制，后台部署和手机热点可用性也会影响远程功能。
